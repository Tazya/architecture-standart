Для решения задачи было принято решение использовать микросервис, который будет отвечать за хранение и предоставление актуальных ставок по депозитам. Микросервис будет взаимодействовать с АБС для получения актуальных данных о ставках и будет предоставлять API для системы кол-центра банка.
Для решения проблемы передачи информации в партнёрский кол-центр, было решено использовать файловый обмен. Микросервис будет генерировать файлы с актуальными ставками и отправлять их по почте через почтовый сервер банка.

**Недостатки, ограничения, риски**

Подробно опишите здесь недостатки, ограничения и риски выбранного решения.

### Недостатки:

1. **Зависимость от микросервиса ставок**: Если микросервис будет недоступен, то система кол-центра не сможет получить актуальные ставки.
2. **Зависимость от почтового сервера**: Если почтовый сервер будет недоступен, то партнёрский кол-центр не получит актуальные ставки.
3. **Сложность интеграции с партнёрским кол-центром**: Потребуется разработка механизма для генерации и отправки файлов с актуальными ставками, что может потребовать дополнительных усилий.

### Ограничения:

1. **Отсутствие возможности API-вызовов**: Партнёрский кол-центр не может использовать API для получения актуальных ставок, что ограничивает возможности интеграции.
2. **Отсутствие горизонтального масштабирования АБС**: Это ограничивает возможности системы в плане обработки большого количества запросов и увеличения нагрузки.

### Риски:

1. **Риск неактуальности данных**: Если микросервис ставок не будет обновляться вовремя, то система кол-центра может предоставлять устаревшую информацию клиентам.
